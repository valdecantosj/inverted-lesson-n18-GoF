Singleton

¿Cómo garantizo una única instancia con acceso global?

Contexto / Problema

Se admite exactamente una de una clase —es un «singleton»—. Los objetos necesitan un único punto de . El problema exige restringir la creación a una única instancia y proveer una vía accesible desde distintas partes.

Solución

Defina un método estático de la clase que devuelva el singleton (getInstancia):

  • La primera vez crea la instancia; las siguientes únicamente la devuelven.
  • El constructor es de acceso restringido (-) para impedir que el código cliente cree instancias con new.
  • Centraliza el control de creación en la propia clase garantizando acceso compartido.

Ejemplo

  • NuevaEra (Larman): Solo se necesita una FactoriaDeServicios y se la invoca desde varios lugares: FactoriaDeServicios.getInstancia().getAdaptadorContabilidad(). Pasarla como parámetro es posible, pero poco conveniente.
  • En la clase (Pedidos): Se tiene una única FactoriaDeServicios utilizada para validar pedidos y procesar pagos en todo el sistema.

Representación en UML

  • instance y getInstance() subrayados: miembros estáticos (a nivel de clase).
  • Singleton(): constructor con acceso restringido (-), evitando que los clientes usen new.
  • Nota: comprueba si instance es null; si no existe la crea, posteriormente devuelve siempre esa misma.
  • Client: accede al Singleton únicamente mediante getInstance().

Discusión y Concurrencia

  • Multihilo: La representa una sección crítica y requiere sincronización para ser . Larman la prefiere a la impaciente porque evita trabajo de creación si nunca se accede a ella.
  • Instancia vs. Estático: Larman prefiere una instancia con métodos de instancia antes que métodos de clase estáticos, pues permite derivar subclases, implementar interfaces y habilitar polimorfismo.
  • Costo: Introduce una dependencia global fuerte que debe estar justificada, puede ocultar problemas de diseño y complica las pruebas unitarias.

Patrones relacionados

Factory y Fachada suelen accederse mediante Singleton. También Abstract Factory, Builder y Prototype pueden implementarse como Singleton.
