Singleton

¿Cómo garantizo una única instancia con acceso global?

Contexto / Problema

¿Qué pasa cuando sólo necesitamos una instancia de una clase en todo el proceso y distintos lugares del sistema necesitan acceder a ella? El problema tiene dos partes:

Se admite exactamente una instancia de una clase —es un «single-ton»—. Y Los objetos necesitan un único punto de acceso global.

Solución

Defina un método estático de la clase que devuelva el singleton (getInstancia). La primera vez crea la ; las siguientes la devuelven. Da a esa única instancia.

Ejemplo

En el mismo sistema solo se necesita UNA ÚNICA INSTANCIA de FactoriaDeServicios y que se la invoque desde varios lugares.

Cuando se necesita usar el singleton, no crea directamente un objeto con new. En cambio, solicita la instancia mediante el método de acceso, por ejemplo, FactoriaDeServicios.getInstancia(); la primera vez se crea, las siguientes únicamente la devuelven.

Singleton = una sola instancia + acceso común a esa instancia. -> está diseñada para impedir que el resto del sistema cree otras instancias directamente.

Representación en UML

  • instance y getInstance() subrayados: miembros estáticos (a nivel de clase). Almacena la única instancia de la clase y permite obtener la misma, respectivamente.
  • Singleton() con acceso restringido (-): el cliente no puede usar new. (Private)
  • Si instance es null la crea; luego devuelve siempre la misma.
  • Client: accede al singleton solo mediante getInstance().

Discusión

Con varios hilos, la es una sección crítica: se sincroniza el método (). Larman la prefiere a la impaciente porque evita crear la instancia si nunca se usa. También prefiere una instancia con métodos de instancia antes que métodos estáticos, porque permiten subclases y polimorfismo.

Con esto se garantiza que exista una única instancia de una clase cuando el diseño requiere que todos los clientes trabajen con el mismo objeto, proporcionando además un punto de acceso a esa instancia. Conseguimos evitar la creación de múltiples instancias; compartir una única instancia entre diferentes partes del sistema; centralizar el acceso a esa instancia; controlar su creación desde la propia clase.

Costo: dependencia global fuerte que debe justificarse; dificulta las pruebas unitarias.

Patrones relacionados

Factoría y Fachada (se suelen acceder mediante Singleton). También Abstract Factory, Builder y Prototype pueden implementarse como Singleton.
