Adaptador (Adapter)

¿Cómo resolver interfaces incompatibles?

Contexto / Problema

¿Cómo resolver interfaces incompatibles, o proporcionar una interfaz estable para componentes parecidos con diferentes interfaces? El problema aparece cuando tenemos un componente que ya existe y posee una funcionalidad que queremos utilizar, pero la interfaz mediante la cual ofrece esa funcionalidad no coincide con la que nuestro sistema espera utilizar.

Solución

Convierta la original de un componente en otra interfaz, mediante un objeto adaptador intermedio:

  • Es un nivel de que desacopla al de la clase externa.
  • Utiliza para intercambiar componentes mediante un contrato común.
  • Aporta frente a las APIs externas.

Ejemplo

  • NuevaEra (Larman): Debe soportar calculadores de impuestos, contabilidad y autorización de pagos externos, cada uno con su API. Se define IAdaptadorCalculadorDeImpuestos y adaptadores por servicio como AdaptadorMasterEnImpuestos y AdaptadorImpuestosPro.
  • En la clase (Pedidos): Interfaz IPago con MercadoPagoAdapter y PayPalAdapter traduciendo las llamadas hacia sus respectivos SDKs.

Representación en UML

  • Client: usa la interfaz Target y no conoce al Adaptee.
  • Target «interface»: el contrato que espera la aplicación.
  • Adapter: implementa Target (realización) y traduce las llamadas.
  • Adaptee: componente existente con otra interfaz. La asociación continua indica que el Adapter lo contiene y le delega.

Discusión y Variantes

  • Beneficios: El cliente usa una interfaz estable, se reutilizan componentes sin modificar el y las diferencias quedan aisladas en el adaptador.
  • Costo: Un objeto más (indirección adicional); si el adaptador acumula demasiada lógica, se debe revisar el diseño.
  • Variantes: Object Adapter (composición, la más flexible en C#) y Class Adapter (herencia).

Patrones relacionados

  • GRASP: Polimorfismo, Indirección, Variaciones Protegidas.
  • GoF: Fachada (simplifica un subsistema; Adapter hace compatibles interfaces), Decorator, Proxy y Bridge. Un adaptador de recursos es una clase de Fachada, pero se llama adaptador por su énfasis en adaptar interfaces.
