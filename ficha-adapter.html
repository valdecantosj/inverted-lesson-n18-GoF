Adaptador (Adapter)

¿Cómo resolver interfaces incompatibles?

Contexto / Problema

¿Cómo resolver interfaces incompatibles, o proporcionar una interfaz estable para componentes parecidos con diferentes interfaces?

Solución

Convierta la interfaz original de un componente en otra interfaz, mediante un objeto adaptador intermedio (entre el Target y el ).

Es un nivel de con que da frente a las APIs externas.

Ejemplo

Nuestro sistema de pedidos (cliente) tiene que permitirnos procesar el pago de los mismos mediante dos métodos de pago conocidos (Mercado Pago y PayPal) cada uno con su API de proovedores externos, con sus respectivas interfaces (todas diferentes).

El cliente no conoce la interfaz incompatible de los SDK de dichas empresas. Solo sabe de una interfaz IPago con el contrato polimórfico procesarPago(monto), y los adaptadores concretos (mercadoPagoAdapter, y PayPalAdapter) implementan esa interfaz y traducen la peticion a cada Adaptee.

Entonces el sistema no va a tener problema en procesar el pago ya que el adaptador le permite comunicarse con los componentes externos. Vea el diagrama UML dado en la presentacion.

Representación en UML

  • Client: usa la interfaz Target y no conoce al Adaptee.
  • Target «interface»: el contrato que espera la aplicación.
  • Adapter: implementa Target (realización: línea discontinua + triángulo hueco) y traduce las llamadas.
  • Adaptee (adaptado): componente existente con otra interfaz. La asociación continua indica que el Adapter lo contiene y le delega.

Discusión

Beneficios:

El cliente usa una interfaz estable, se reutilizan componentes sin modificar el Adaptee y las diferencias quedan aisladas en el adaptador.

Costo: un objeto más (indirección adicional); si el adaptador acumula mucha lógica, hay que revisar el uso del patrón.

Variantes: Object Adapter (mediante referencia al objeto) y Class Adapter (usa herencia).

Patrones relacionados

GRASP: Polimorfismo, Indirección, Variaciones Protegidas.

GoF: Fachada (simplifica un subsistema; Adapter hace compatibles interfaces), Decorator, Proxy y Bridge.

Un adaptador de recursos es una clase de Fachada, pero se llama adaptador por su énfasis en adaptar interfaces.
